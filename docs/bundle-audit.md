# Аудит загрузки и размера сборки

Обновлено 2026-11-13. Сравнение исходного аудита `refactor/styles`
от 2026-11-10 и финальной сборки `perf/editor-loading`.
Angular Build 19.2.27, Milkdown Crepe 7.22.3.

Редактор и его CSS больше не загружаются вместе со списком заметок.
Оценка передачи для графа `/notes` уменьшилась примерно на 71%;
общий вес сборки почти не изменился. Основной результат — изменение
момента загрузки и устранение повторного сетевого ожидания CSS.

Исходный снимок сделан до финального переноса CSS пикера цвета.
Сравнение показывает результат всего прохода между снимками,
а не изолированный эффект одной строки конфигурации.

## Основание и границы анализа

Отчёт получен командой:

```bash
npm run build -- --stats-json
```

`dist/skein/stats.json` содержит граф импортов и вклад исходных модулей
в выходные файлы. Каталог `dist` исключён из Git; при повторной проверке
отчёт нужно создать заново. В исходном снимке было 131 JS-чанк и 1470
входных файлов; в итоговом — 134 JS-чанка, два CSS-бандла и 1474 входных
файла. Проверены граф статических зависимостей, отдельные точки входа
и настройки редактора в установленной версии.

Размеры после сжатия оценены способом Angular CLI: Brotli, с сохранением
исходного размера для файлов меньше 1 КБ. Это оценка передачи JS и CSS
при холодном кэше, а не измерение фактического ответа Cloudflare.
HTML, изображения и шрифты в таблицу не включены.

Реальное время старта, выполнение JavaScript, расход памяти и поведение
на слабом устройстве не измерялись. Размер файла сам по себе не определяет
время выполнения его кода.

## Находки и порядок работ

### 1. Отделить тяжёлый редактор от списка

Статус: выполнено.

В [notes.routes.ts](../src/app/features/notes/notes.routes.ts) `NoteDetailComponent`
остаётся обычным компонентом внутри ленивого раздела заметок. Тяжёлая граница
перенесена в его шаблон: `@defer (on immediate)` загружает
`MarkdownEditorComponent`. Заголовок и активная заметка доступны,
пока загружается Milkdown. Откладывать сам NoteDetail вместе с редактором
означало бы задерживать и активацию маршрута.

Query `viewChild<MarkdownEditorComponent>('editor')` ищет экземпляр по
шаблонной ссылке. TypeScript-тип не создаёт runtime-обращения к классу
отложенного компонента вне `@defer`. Перед навигацией сохранён вызов `flush()`.
Markdown-парсер для кратких описаний списка по-прежнему нужен до редактора.

### 2. Явно определить состав Crepe

Статус: проверено; готовый Crepe сохранён.

В [MarkdownEditorComponent](../src/app/shared/markdown-editor/markdown-editor.component.ts)
используется готовый `Crepe`. LaTeX включён по умолчанию. В выходном коде:

- KaTeX занимает 269 141 байт до сжатия;
- Vue, используемый интерфейсом Milkdown, занимает суммарно 65 951 байт;
- плагины diff и streaming занимают 9110 и 6708 байт соответственно,
  хотя AI-функции Crepe выключены по умолчанию.

В Crepe 7.22.3 общий загрузчик статически импортирует функции и выбирает
их во время выполнения. Отключение функции флагом не гарантирует удаления
её кода из сборки. Проверять результат по новому `stats.json`.

Проверен официальный `CrepeBuilder` с отдельными подключениями возможностей
при сохранении эквивалентного набора функций. В изолированном сравнении
выигрыш составил около 11 КБ после Brotli, ценой сопровождения порядка
десяти подключений и их настроек. Для текущего проекта выбран готовый Crepe.
Математические формулы сохранены. Это осознанный компромисс состава редактора,
а не утверждение об отсутствии возможностей дальнейшей оптимизации.

### 3. Проверить загрузку CSS редактора

Статус: выполнено; HTTP-кэш ресурсов остаётся отдельной задачей.

Импорты Crepe удалены из [styles.css](../src/styles.css) и собраны в
`markdown-editor.styles.css`. В `angular.json` задан отдельный CSS-бандл
`editor` с `inject: false`. Установленный Angular 19 сохраняет для него
имя `editor.css`, несмотря на `outputHashing: 'all'`.

Корневой `EditorStylesService` добавляет один `link` в `document.head`
и хранит статус загрузки. Вызов из NoteDetail начинает загрузку CSS
параллельно с JS редактора. При отказе элемент удаляется, следующая попытка
разрешена. При успешной загрузке элемент и статус сохраняются на время
жизни приложения; пересоздание компонента не вызывает новый запрос CSS.

В Network пользователь обнаружил повторные ответы `304` с задержкой около
двух секунд под искусственным 3G. Проверка заголовков локального Wrangler
показала `Cache-Control: public, max-age=0, must-revalidate`. Повторная
проверка актуальности не передаёт тело файла, но требует сетевого ответа.
Сервис устранил повторное подключение и это ожидание внутри открытой страницы.

Перенос в `styleUrl` с `ViewEncapsulation.None` проверен отдельной сборкой:
CSS действительно попадает в JS ленивого компонента, но превышает общий
`anyComponentStyle` 4/8 КБ. Сохранены отдельный CSS и строгий общий бюджет;
для бандла `editor` добавлены собственные пороги 100/120 КБ.
Прямой импорт CSS в TS в проверенной конфигурации не собрался из-за
отсутствия загрузчиков шрифтов; автоматически подключаемый lazy CSS
для такого варианта не был подтверждён.

KaTeX также создаёт 60 файлов шрифтов общим размером 1 076 572 байта.
Это файлы форматов WOFF2, WOFF и TTF, а не обязательный трафик страницы:
браузер выбирает поддерживаемый формат и нужные начертания.

Фиксированные URL `editor.css` и `icons.svg` пока не версионированы.
Долгий `immutable`-кэш без изменения URL при обновлении назначать нельзя.
Повторные проверки спрайта сохраняются; их нужно разбирать как задачу
версионирования и HTTP-кеша, а не создавать отдельный сервис для каждой иконки.

### 4. Языки CodeMirror: сохранить загрузку по необходимости

Приоритет пересмотра: низкий. Статус: существующая загрузка проверена по коду.

После статических зависимостей раздела остаётся 121 JS-чанк суммарным размером
1 256 932 байта. Все относятся к языковым парсерам CodeMirror/Lezer,
включая общие части. Из них 115 — отдельные точки входа языковой поддержки.

`@codemirror/language-data` содержит динамические импорты.
`LanguageLoader` Milkdown вызывает загрузчик конкретного языка при работе
с соответствующим блоком кода. Наличие файлов в `dist` не означает
одновременное выполнение всех запросов при запуске.

Ограничение списка языков допустимо как продуктовое решение, но не является
первым шагом оптимизации старта. Если выбирать собственный список,
сохранить динамическую загрузку. Проверить выбранные языки в Network.

### 5. Диалоги и небольшие зависимости

Приоритет: после основных изменений редактора. Статус: не выполнено.

- Форма пространства импортирована в `SpaceRailComponent` обычным способом
  и приходит вместе с оболочкой. Общий чанк формы и пикеров — около 57 КБ,
  включая около 42 КБ Angular Forms. Рассмотреть загрузку диалогов при открытии
  и измерить фактический эффект после отделения редактора.
- В стартовом графе присутствует около 70,6 КБ Angular CDK. Вклад включает
  Overlay, Dialog и доступность. Сам размер не является основанием заменять CDK;
  момент подключения проверять вместе с диалогами.
- Повторного включения одного исходного JS-файла в разные чанки не обнаружено.
  Есть две физические копии `nanoid` 6.0.2 с вкладом 409 и 413 байт;
  это не приоритет текущего прохода.
- `extend` занимает 1203 байта в чанке заметок и нужен `unified` для глубокого
  копирования и объединения настроек. Установленный `unified` 11.0.5 сохраняет
  эту зависимость. Изолированное сравнение с ESM-заменой показало лишь
  десятки байт разницы после gzip; патч или форк зависимости не обоснован.
  Предупреждение сохранено: `allowedCommonJsDependencies` его скрывает,
  но не уменьшает сборку.
- Отдельный бюджет CSS `editor` добавлен. Контроль размера JS-ветки редактора
  остаётся возможным следующим шагом: один `initial` не контролирует
  всю загрузку первого экрана после перенаправления на `/notes`.

## Состояния интерфейса и проверка результата

- Общие лёгкие компоненты ошибки и загрузки доступны без Milkdown.
  Отказ CSS показывается даже при ещё загружающемся JS; отказ JS обрабатывает
  `@error`. После загрузки CSS `afterNextRender` дожидается DOM `#host`,
  затем создаётся редактор. До готовности содержимое скрыто.
- Статус инициализации `pending | ready | error` управляет отображением.
  Исключения из создания передаются Angular `ErrorHandler`.
- Один порог 150 мс в NoteDetail через `timer` и `toSignal` применяется
  к индикаторам обеих стадий. Порог не перезапускается при смене стадии,
  не задерживает готовое содержимое и показ ошибки.
- Пользователь подтвердил production-сборку и прохождение тестов,
  первое и повторное открытие, сохранение перед быстрой навигацией,
  ошибки CSS и JS, восстановление после блокировки CSS и ранний показ
  ошибки CSS при медленном JS. Проверки выполнялись в том числе
  с ограничением сети в DevTools.
- Перехват ошибки инициализации проверен искусственным отказом промиса
  до `new Crepe`, затем временный код удалён. Это не проверка очистки
  частично инициализированного Milkdown при настоящем внутреннем отказе.
  Формальные замеры CPU и памяти на слабом устройстве не выполнялись.

Отдельный режим чтения пока не вводится. После устранения повторной
загрузки CSS дополнительная логика переключения режимов не обоснована
текущим наблюдением о задержке. Содержимое заметки по-прежнему требует
успешной первой загрузки редактора.

## Как проверять следующие изменения

1. Сохранить базовые цифры и менять одну границу загрузки или одну возможность.
2. Снова выполнить `npm run build -- --stats-json`.
3. Сравнить `outputs`, `bytesInOutput` и граф статических/динамических импортов.
   Размер исходника, вклад в выходной файл и передаваемый размер различаются.
4. В DevTools Network проверить реальные запросы с холодным кэшем:
   список, первое открытие заметки, заметка с кодом, повторное открытие.
5. В Performance измерить выполнение JavaScript, создание редактора
   и отзывчивость; при необходимости использовать замедление CPU и сети.
6. Проверить сохранение текста, переключение заметок, историю навигации,
   оформление и оставленные функции редактора. Зафиксировать результат.

Отдельно разобрать этот процесс в режиме обучения: чтение отчёта сборки,
различие размера и скорости, поиск импортирующего модуля, выбор эксперимента
и оценка цены изменения. Такой анализ опирается на штатные инструменты
Angular, esbuild и браузера.
