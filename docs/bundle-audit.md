# Аудит загрузки и размера сборки

Дата: 2026-11-10. Снимок рабочего дерева ветки `refactor/styles` до оптимизации
загрузки редактора. Angular Build 19.2.27, Milkdown Crepe 7.22.3.

Измерения ниже относятся к сборке до переноса CSS пикера цвета в шаблон.
После завершения прохода стилей пользователь получил `Initial total`
466,61 КБ и оценку передачи 109,38 КБ. Перед оптимизацией нужно заново
создать `stats.json` и зафиксировать исходные размеры для сравнения.

## Основание и границы анализа

Отчёт получен командой:

```bash
npm run build -- --stats-json
```

`dist/skein/stats.json` содержит граф импортов и вклад исходных модулей
в выходные файлы. Каталог `dist` исключён из Git; при повторной проверке
отчёт нужно создать заново. Проанализированы все 131 JS-чанк и 1470 входных
файлов, глобальный CSS и настройки редактора в установленной версии.

Размеры после сжатия оценены способом Angular CLI: Brotli, с сохранением
исходного размера для файлов меньше 1 КБ. Это оценка передачи JS и CSS
при холодном кэше, а не измерение фактического ответа Cloudflare.
HTML, изображения и шрифты в таблицу не включены.

Реальное время старта, выполнение JavaScript, расход памяти и поведение
на слабом устройстве не измерялись. Размер файла сам по себе не определяет
время выполнения его кода.

## Базовые размеры

Первые три строки накопительные: включают статические зависимости
соответствующих точек входа и глобальный CSS. При открытии `/notes`
маршруты оболочки и заметок загружаются сразу после запуска приложения.

| Набор файлов | До сжатия, КБ | Оценка передачи, КБ |
| --- | ---: | ---: |
| `Initial total` Angular CLI | 465,85 | 109,28 |
| Вместе с оболочкой приложения | 526,69 | 123,44 |
| Вместе с разделом `/notes` | 2073,10 | 533,73 |
| Все созданные JS и глобальный CSS | 3330,03 | 952,50 |

Последняя строка не означает одновременную загрузку всех файлов.
CSS компонента выбора цвета встроен в JavaScript и повторно в итог не сложен.

## Находки и порядок работ

### 1. Отделить загрузку отдельной заметки от списка

Приоритет: высокий. Статус: не выполнено.

В [notes.routes.ts](../src/app/features/notes/notes.routes.ts) обычный импорт
`NoteDetailComponent` приводит к цепочке:

```text
notes.routes → NoteDetailComponent → MarkdownEditorComponent → Milkdown
```

Редактор загружается при входе в список, даже когда отображается placeholder
и ни одна заметка не открыта. Крупные файлы этой части:

| Файл в базовой сборке | Содержимое | До сжатия, КБ | Оценка передачи, КБ |
| --- | --- | ---: | ---: |
| `chunk-3RIX7VVL.js` | Маршрут заметок, Milkdown, ProseMirror, KaTeX и другие зависимости | 1192,64 | 309,10 |
| `chunk-NPCH2MEU.js` | Общие части CodeMirror и Lezer | 318,32 | 89,80 |
| `chunk-TQEXSKUF.js` | CodeMirror autocomplete | 35,45 | 11,39 |

Первый шаг — `loadComponent` для маршрута `:id` с удалением обычного импорта
компонента деталей. После изменения пересобрать отчёт и проверить граф:
редактор не должен быть статической зависимостью списка. Точное уменьшение
первой загрузки пока не измерено; часть Markdown-парсера нужна превью списка.

Это изменение момента загрузки, а не уменьшение общего размера редактора.
Проверить вход в пустой список, прямую ссылку на заметку, первое открытие,
переключение заметок и сохранение последних изменений.

### 2. Явно определить состав Crepe

Приоритет: высокий. Статус: не выполнено.

В [MarkdownEditorComponent](../src/app/shared/markdown-editor/markdown-editor.component.ts)
используется готовый `Crepe`. LaTeX включён по умолчанию. В выходном коде:

- KaTeX занимает 269 141 байт до сжатия;
- Vue, используемый интерфейсом Milkdown, занимает суммарно 65 951 байт;
- плагины diff и streaming занимают 9110 и 6708 байт соответственно,
  хотя AI-функции Crepe выключены по умолчанию.

В Crepe 7.22.3 общий загрузчик статически импортирует функции и выбирает
их во время выполнения. Отключение функции флагом не гарантирует удаления
её кода из сборки. Проверять результат по новому `stats.json`.

Рассмотреть официальный `CrepeBuilder` из `@milkdown/crepe/builder`
и подключения отдельных возможностей через `@milkdown/crepe/feature/*`.
Сохранить согласованный набор функций редактора и существующую синхронизацию.
Цена подхода — явное сопровождение подключений и их настроек.

Нужность математических формул определить отдельно. Если они нужны,
продумать момент их загрузки; если нет — исключить соответствующие подключения
JavaScript и CSS. Не заменять сам редактор ради уменьшения одного пакета.

### 3. Проверить загрузку CSS редактора

Приоритет: средний. Статус: не выполнено.

В [styles.css](../src/styles.css) стили Crepe подключены глобально.
Фактический общий файл: 117,41 КБ до сжатия и около 15,10 КБ после Brotli.

В сравнении обработки CSS в памяти удаление стилей редактора уменьшало
результат примерно на 87 КБ до сжатия; исключение только LaTeX-стилей —
примерно на 27 КБ. Это ориентиры по составу, а не замер итоговой сборки
после готового изменения загрузки.

KaTeX также создаёт 60 файлов шрифтов общим размером 1 076 572 байта.
Это файлы форматов WOFF2, WOFF и TTF, а не обязательный трафик страницы:
браузер выбирает поддерживаемый формат и нужные начертания.

Решение по CSS принимать вместе с составом редактора. Учитывать область
действия стилей, появление оформления при первом открытии и бюджет CSS
компонентов Angular; простой перенос глобального CSS в `styleUrl`
не считать готовым решением.

### 4. Языки CodeMirror: сохранить загрузку по необходимости

Приоритет пересмотра: низкий. Статус: существующая загрузка проверена по коду.

После статических зависимостей раздела остаётся 121 JS-чанк суммарным размером
1 256 932 байта. Все относятся к языковым парсерам CodeMirror/Lezer,
включая общие части. Из них 115 — отдельные точки входа языковой поддержки.

`@codemirror/language-data` содержит динамические импорты.
`LanguageLoader` Milkdown вызывает загрузчик конкретного языка при работе
с соответствующим блоком кода. Наличие файлов в `dist` не означает
одновременное выполнение всех запросов при запуске.

Ограничение списка языков допустимо как продуктовое решение, но не является
первым шагом оптимизации старта. Если выбирать собственный список,
сохранить динамическую загрузку. Проверить выбранные языки в Network.

### 5. Диалоги и небольшие зависимости

Приоритет: после основных изменений редактора. Статус: не выполнено.

- Форма пространства импортирована в `SpaceRailComponent` обычным способом
  и приходит вместе с оболочкой. Общий чанк формы и пикеров — около 57 КБ,
  включая около 42 КБ Angular Forms. Рассмотреть загрузку диалогов при открытии
  и измерить фактический эффект после отделения редактора.
- В стартовом графе присутствует около 70,6 КБ Angular CDK. Вклад включает
  Overlay, Dialog и доступность. Сам размер не является основанием заменять CDK;
  момент подключения проверять вместе с диалогами.
- Повторного включения одного исходного JS-файла в разные чанки не обнаружено.
  Есть две физические копии `nanoid` 6.0.2 с вкладом 409 и 413 байт;
  это не приоритет текущего прохода.
- `extend` занимает 1203 байта в чанке заметок и нужен `unified` для глубокого
  копирования и объединения настроек. Установленный `unified` 11.0.5 сохраняет
  эту зависимость. Проверенная совместимая ESM-замена не найдена.
  Подмена реализации ради предупреждения не обоснована текущими измерениями.
  Точечное `allowedCommonJsDependencies` может документировать принятое
  ограничение, но само по себе ничего не оптимизирует; решение пока отложено.
- После определения новых границ загрузки рассмотреть отдельный бюджет
  для крупного маршрута или редактора: один `initial` не контролирует
  всю загрузку первого экрана после перенаправления на `/notes`.

## Как проверять следующие изменения

1. Сохранить базовые цифры и менять одну границу загрузки или одну возможность.
2. Снова выполнить `npm run build -- --stats-json`.
3. Сравнить `outputs`, `bytesInOutput` и граф статических/динамических импортов.
   Размер исходника, вклад в выходной файл и передаваемый размер различаются.
4. В DevTools Network проверить реальные запросы с холодным кэшем:
   список, первое открытие заметки, заметка с кодом, повторное открытие.
5. В Performance измерить выполнение JavaScript, создание редактора
   и отзывчивость; при необходимости использовать замедление CPU и сети.
6. Проверить сохранение текста, переключение заметок, историю навигации,
   оформление и оставленные функции редактора. Зафиксировать результат.

Отдельно разобрать этот процесс в режиме обучения: чтение отчёта сборки,
различие размера и скорости, поиск импортирующего модуля, выбор эксперимента
и оценка цены изменения. Такой анализ опирается на штатные инструменты
Angular, esbuild и браузера.
