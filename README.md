# Skein

[Открыть демо](https://skein.sanya-super7.workers.dev)

Приложение для учебных заметок и подготовки к техническим собеседованиям: Markdown-редактор, автосохранение и пространства для организации материала по контексту.

Идея проекта выросла из простой проблемы: полезные объяснения, фрагменты кода и ответы ИИ теряются в переписках и сохранённых сообщениях. Вместо одной длинной заметки Skein позволяет разбить тему на небольшие материалы: например, собрать в пространстве «JavaScript» отдельные заметки о типах, операторах и замыканиях.

Это самостоятельный учебный проект для практики Angular, TypeScript и проектирования интерфейсов. Приложение находится в разработке; сейчас работает в браузере и хранит данные в `localStorage`, без бэкенда и аккаунтов.

## Возможности

- **Markdown-редактор без переключения режимов.** Текст оформляется по мере ввода; доступны таблицы, списки задач и блоки кода.
- **Создание, переименование и удаление заметок.** Изменения заголовка и текста сохраняются автоматически.
- **Список заметок с текстовым превью.** Markdown преобразуется в обычный текст для отображения в списке.
- **Создание и редактирование пространств.** Общий диалог позволяет выбрать название, иконку и цвет с предпросмотром и валидацией названия, включая ограничение в 50 символов. При редактировании сохранение доступно, когда данные корректны и отличаются от исходных; возврат к прежним значениям снова отключает кнопку.
- **Просмотр заметок по пространству.** Новая заметка, созданная внутри пространства, сразу связывается с ним.
- **Удаление с учётом контекста.** В пространстве действие над заметкой убирает только её связь с этим пространством; во «Всех заметках» удаляет саму заметку и её связи. Удаление пространства требует подтверждения и сохраняет заметки.
- **Три цветовые темы.** Graphite, Midnight и Macchiato; выбор запоминается между посещениями.
- **Прямые ссылки.** Заметки и пространства открываются по собственным URL.

## Архитектура и технические решения

### Состояние и границы ответственности

[NotesStore](src/app/data/notes.store.ts) и [SpacesStore](src/app/data/spaces.store.ts) хранят данные в приватных сигналах и предоставляют публичные сигналы через `asReadonly()`. Компоненты могут читать сторы напрямую, а изменения заметок и пространств выполняют через [LibraryFacade](src/app/data/library.facade.ts).

Фасад координирует операции над связанными данными: например, при удалении заметки удаляет и её связи с пространствами. Сторы обновляют массивы и объекты иммутабельно; сохранение в `localStorage` выполняется через `effect`.

Сигналы используются для состояния и производных значений. RxJS остаётся для потоков событий: например, реакции на навигацию с автоматическим завершением подписки через `takeUntilDestroyed`.

### Пространства как контексты

Заметки, пространства и связи `{ noteId, spaceId }` хранятся отдельно. Модель поддерживает связь «многие ко многим»: одна заметка может принадлежать нескольким пространствам без копирования текста. Интерфейс добавления существующей заметки в другое пространство ещё предстоит реализовать.

Выборка заметок пространства находится в `LibraryFacade`: один `computed` собирает `Set` идентификаторов из связей, второй фильтрует заметки через `Set.has()`. Это позволяет избежать повторного обхода всех связей для каждой заметки. Изменение текста заметки не требует заново собирать набор идентификаторов, пока пространство и связи остаются прежними.

### Интеграция стороннего редактора

[MarkdownEditorComponent](src/app/shared/markdown-editor/markdown-editor.component.ts) связывает Milkdown Crepe с Angular через входной сигнал и событие изменения текста:

- редактор создаётся в `afterNextRender`, когда доступен DOM;
- входящее значение синхронизируется через `effect`, а последнее отправленное значение запоминается, чтобы не возвращать редактору его собственные изменения;
- при потере фокуса отправляется актуальный текст, а перед навигацией `NoteDetailComponent` вызывает `flush()`, чтобы сохранить ввод, ещё не переданный отложенным событием редактора;
- запоздалое событие сверяется с текущим содержимым редактора, чтобы не применить устаревший текст после переключения заметки;
- при уничтожении компонента уничтожается экземпляр редактора.

### Превью Markdown через синтаксическое дерево

Пайп [markdownToPlain](src/app/shared/markdown-to-plain/markdown-to-plain.pipe.ts) разбирает Markdown в дерево mdast с поддержкой GFM, затем собирает текст с разделителями между блоками и ячейками таблиц. HTML-разметка и маркеры задач не попадают в превью.

Такой подход заменил набор регулярных выражений: обработку синтаксиса выполняет парсер, а код приложения определяет, как представить результат в списке заметок.

### Формы и проверка данных

Создание и редактирование пространства используют общий диалог с типизированными Reactive Forms и `NonNullableFormBuilder`. При редактировании исходные значения передаются через `DIALOG_DATA`. Форма хранит локальный черновик, проверяет название и возвращает `SpaceDraft` вызывающему компоненту, который сохраняет его через фасад.

Для проверки наличия изменений поток `valueChanges` преобразуется через `toSignal` в сигнал с полным снимком значений формы. `computed` сравнивает его с исходными данными; название сравнивается после `trim()`, как при сохранении. Неизменённый результат блокируется и кнопкой, и проверкой в `submit()`. Источником значений остаётся форма.

Данные из `localStorage` читаются как `unknown` и проходят проверки во время выполнения: записи неподходящей структуры отбрасываются, значения иконок и цветов сверяются с допустимыми вариантами. Это отдельная граница проверки: типы TypeScript сами по себе не проверяют содержимое хранилища. Ручные предикаты необходимо обновлять вместе с моделью.

### Маршрутизация

Общий компонент списка и редактора используется и для всех заметок, и для выбранного пространства. Маршруты заметок загружаются лениво; параметры передаются во входные сигналы компонентов через `withComponentInputBinding()`.

| URL                          | Представление                    |
| ---------------------------- | -------------------------------- |
| `/notes`                     | Все заметки                      |
| `/notes/:id`                 | Заметка из общего списка         |
| `/spaces/:spaceId/notes`     | Заметки выбранного пространства  |
| `/spaces/:spaceId/notes/:id` | Заметка в контексте пространства |

### Темы и общий язык интерфейса

Цвета тем заданы CSS-переменными под `[data-theme]` и связаны с Tailwind через `@theme inline`. Общие стили кнопок, полей и сообщений формы вынесены в `styles/controls.css`; отображение иконки и цвета пространства переиспользуется через `SpaceBadgeComponent`.

Диалоги и меню построены на Angular CDK с собственным оформлением. В форме используются нативные радиокнопки, подписи и ARIA-связи для сообщений об ошибках; для интерактивных элементов предусмотрены стили клавиатурного фокуса и учёт `prefers-reduced-motion`.

## Локальный запуск

Для запуска нужны совместимая с Angular 19 версия Node.js (например, 22.x) и npm. Команды выполняются из корня проекта — папки `Burmaldense`.

```bash
npm ci
npm start
```

Приложение доступно по адресу `http://localhost:4200`.

Сборка для публикации:

```bash
npm run build
```

Готовые статические файлы находятся в `dist/skein/browser/`.

## Деплой

Приложение опубликовано на Cloudflare Workers Static Assets.
Изменения в `main` автоматически запускают сборку и публикацию через интеграцию с GitHub.

Настройки находятся в `wrangler.jsonc`: каталог сборки и возврат `index.html` для маршрутов Angular. Версия Node.js для облачной сборки задана в `.node-version`.

Демо хранит данные в `localStorage` браузера посетителя. Заметки с локального адреса разработки на опубликованный сайт не переносятся.

## Тесты

```bash
# Запуск с отслеживанием изменений
npm test

# Однократный запуск без видимого окна браузера
npm test -- --watch=false --browsers=ChromeHeadless
```

Для этих команд нужен установленный Google Chrome. Есть проверки поведения стора заметок, выбора темы и преобразования Markdown, а также тесты создания компонентов. Покрытие пользовательских сценариев, фасада и работы с пространствами ещё предстоит расширить.

## Ограничения и дальнейшие шаги

Данные привязаны к браузеру и его профилю. Синхронизации, резервного копирования и экспорта пока нет; очистка данных сайта удалит сохранённые заметки. Адаптация интерфейса для небольших экранов ещё не завершена.

Ближайшие направления:

- Добавление существующих заметок в пространства.
- Поиск по заметкам.
- Расширение тестов поведения и проверка доступности интерфейса.
- Бэкенд, аккаунты, синхронизация.

Отдельное направление развития — MCP-интеграция, чтобы пользователь мог попросить ИИ-агента сохранить полезный материал в Skein. Сейчас эта возможность не реализована.
